The mandate

One product, three ways for an AI to use it.

JType is already both a note app (Markdown documents + folders) and a kanban app (boards / columns / cards / labels) — and it already had an OAuth device flow and bearer sessions. We mirror exactly how the market leaders ship AI access.

◆ Online MCP server

Remote, multi-tenant, OAuth — like Notion & Linear's hosted MCP. Read & manage notes and cards over Streamable HTTP.

▢ Command-line tool

Bundled with desktop, device-auth login — like the Obsidian Local REST API path. Manages docs & projects; binds an Obsidian vault.

✦ Agent Skills

Folders of SKILL.md that teach an agent jtype conventions and drive the CLI/MCP — installed & proven inside jcode.

Design · the key decision

MCP tools dispatch in-process into the existing API

No duplicated SQL. Each tools/call builds an internal HTTP request, forwards the caller's bearer token, and runs it through a clone of the live Axum router via tower::oneshot — the same mechanism the integration tests use. Reuses all tested logic: RBAC, sqlx CAST handling, lamport clocks, version history, WebSocket broadcasts. Zero changes to existing handlers.

Build · the MCP server

Streamable HTTP · OAuth device grant · 14 tools

🔑 Auth that satisfies the MCP spec

Reuses jtype's device flow, repackaged as RFC 8628: /.well-known/oauth-protected-resource + oauth-authorization-server, /api/oauth/device_authorization & /api/oauth/token. Missing token → 401 + WWW-Authenticate challenge. The access token is a jtype session token.

Build · the jtype CLI

Device-auth CLI: docs, projects, Obsidian & a stdio bridge

# log in via the device flow
$ jtype login
  Open: http://localhost:13345/oauth/device?code=425327
  Approve code: 425327
  ✓ Logged in as demo

# manage notes & kanban
$ jtype note create --workspace W ideas/x.md --content -
$ jtype card move --workspace W --board B C --to-column Doing

# enable an Obsidian vault → cloud → AI
$ jtype obsidian enable --vault ~/Vault --workspace W
$ jtype obsidian push        # .md → documents

# expose the same tools over stdio MCP
$ jtype mcp-stdio            # bridges to /mcp

▢ One binary, four jobs

A standalone Rust crate (services/jtype-cli): device-auth client, notes/kanban manager, Obsidian two-way sync (content-hash diff), and a stdio↔HTTP MCP bridge for clients that only speak stdio.

✦ "Enable Obsidian"

Bind any local Markdown folder to a workspace; push/pull sync changed files by hash — turning an Obsidian vault into AI-reachable cloud documents.

Build · Agent Skills

Two verified skills that drive the tools

✦ /jtype-notes

Capture, find, summarize & organize Markdown notes. Encodes path/folder conventions (kebab-case, meetings/…, ideas/…), H1 titles, append-vs-replace judgement, and a search→get→summarize-with-citations workflow.

✦ /jtype-kanban

Board triage: get_board → classify priority → set assignee via list_members → move to advance → summarize counts. Guardrails: resolve real ids before mutating; plan bulk changes first.

Installed into ~/.jcode/skills/ (and the project's .jcode/skills/). jcode surfaces each skill's description in the system prompt and loads the full body on demand — the skill supplies judgement, the MCP/CLI supplies capability.

Reproduce it

Plug JType into any MCP client in one block

// ~/.jcode/config.json  (or any MCP client)
{
  "mcp_servers": {
    "jtype": {
      "type": "http",
      "url":  "http://localhost:13345/mcp",
      "headers": {
        "Authorization": "Bearer <token>"
      }
    }
  }
}

① Get a token

jtype login (device flow) — or any MCP client does the OAuth device grant the server advertises.

② Drop in the skills

Copy jtype-notes / jtype-kanban into ~/.jcode/skills/.

③ Talk to it

"Triage my Launch board and file a kickoff note" — the agent does the rest.
