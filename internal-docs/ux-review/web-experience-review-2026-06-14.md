# JType Web 体验评审报告

## 概览

本轮评审覆盖落地页(`/`)、登录引导(`/login`)、仪表板(`/workspaces`)、帮助中心(`/help` 及其分类/文章页)、对外发布页(`/u/jack`)以及移动端 375px 视口。总体判断:**全站完成度高、功能闭环完整、运行时健康**——多页连续操作未见任何 console 报错,帮助文章页、编辑器工具栏等核心模块的细节打磨到位,无障碍命名覆盖良好(编辑器控件 0 个未命名)。这是一份质量底子扎实的产品。

但本轮核验也暴露出一个**会直接断裂主路径的阻断级问题**:在最主流的移动端 375px 视口下,顶栏导航整体隐藏且无汉堡菜单替代,未登录用户除登录外无任何路径到达帮助/产品区块/外链——这不是"摩擦",而是"路径不可用",列为 P0。

除此之外,核心摩擦集中在三处,且恰好命中用户最初的两个关切:

1. **帮助中心层级过深(对应诉求二:多余点击步骤)**——hub 与分类页全是纯索引,读到第一句正文需穿过 2-3 次点击,且首次进入 `/help` 还要先吃 1-2 秒纯白屏。
2. **移动端导航缺失(对应诉求一:兼容性)**——即上述 P0,叠加全站无页脚,移动端浏览动线首尾皆断。
3. **若干 i18n / 一致性瑕疵(对应诉求一:文案达意与一致性)**——`<html lang="en">` 与中文 UI 不符、中文界面泄漏英文复数"文件s"且计数与实列不一致、对外页 `/u/jack` 空状态残留英文 `No published workspaces yet.`、退出按钮为语义不明的方框图标。

总体结论:**地基稳、门面亮,但"获取信息的最后一公里"和"移动端可达性"是当前最该优先补的两块短板。**

## 评分标准

| 等级 | 含义 | 处置建议 |
|------|------|----------|
| **P0** | 阻断级。主路径不可用、功能不可达,无合理变通。 | 立即修复,优先级高于一切 |
| **P1** | 高。显著阻碍核心任务或损害信任,但存在变通路径。 | 本迭代内修复 |
| **P2** | 中。明显摩擦或一致性缺陷,影响体验质量,不阻断任务。 | 排入近期迭代 |
| **P3** | 低。打磨缺失、轻度冗余,影响观感。 | 有余力时处理 |

## 问题清单

### P0 — 阻断级(1 项)

#### P0-1 移动端(375px)导航整体隐藏且无汉堡菜单替代,帮助/区块/外链全部不可达

- **现象与证据**:在 375px 真实视口截图下,顶栏塌缩为仅 `logo + 登录 →`;导航链接 `流程/界面/AI/发布/帮助/GitHub` 全部 `visible:false`,且**没有汉堡菜单替代**,仅英雄区内"查看流程"锚点按钮可用。进一步确认:DOM 中不存在任何汉堡/移动菜单切换元素,落地页样式仅有 1023px、767px 两档断点。
- **用户影响**:在最主流的移动设备上,未登录访客除"登录"外**无任何可点击路径**到达帮助中心、产品流程/界面/AI/发布等区块或 GitHub 外链——导航能力近乎归零,决策信息被整体截断。这是主路径直接断裂(路径不可用),而非单纯摩擦,直接命中用户对"兼容性"的关切。
- **建议**:在 ≤767px(或 ≤1023px)断点为顶栏加入汉堡菜单(`button`,`aria-label="打开菜单"` + `aria-expanded`),点击展开抽屉/下拉,收纳 `流程/界面/AI/发布/帮助/GitHub` 全部链接;保证键盘可达与焦点管理。至少确保"帮助"与各锚点区块在 375px 可达。

### P1 — 高(6 项)

#### P1-1 帮助中心 hub 与分类页全是纯索引,读到正文需 2-3 次点击(且叠加首屏白屏)

> 直接对应用户诉求二:"帮助文档点进去要穿过多层才看到正文"。

- **现象与证据**:路径为 `/help`(hub,无任何正文)→ `/help/c/{cat}`(文章列表页)→ `/help/c/{cat}/{article}`(真正正文)。从 hub 需 2 次点击,从站点"帮助"导航进入需 **3 次点击**;hub 和分类页**始终看不到任何正文**。叠加首次进入 `/help` 的 1-2 秒纯白屏(见 P1-2)。
- **用户影响**:用户进帮助中心是为读答案,却要穿过两层纯目录页才看到第一句正文,在用户重点吐槽的"帮助层级过深"上构成明显的获取障碍,跳出/流失风险高。
- **建议**:压缩到正文的步数——(1)hub/分类页内联高频文章正文或精选片段,或让分类页默认展开首篇文章;(2)hub 顶部放 3-5 个热门文章 deep link,1 次点击直达 article;(3)把已验证好用的搜索 typeahead 置于最显眼位置作为主路径。
- **备注**:已证实好用的搜索 typeahead 可 1 次点击直达正文,是有效变通出口,故定 P1 而非 P0。

#### P1-2 首次进入 `/help` 整屏纯白 1-2 秒,无骨架屏 / spinner / 任何加载反馈

- **现象与证据**:首次进入 `/help` 出现整屏纯白空白约 1-2 秒(无骨架屏、无 spinner、无任何 affordance),然后才渲染;已多次复现(导航到 `/help` 当刻截图为纯白)。
- **用户影响**:用户点"帮助"(用户重点关切的层级)后 1-2 秒无任何反馈白屏,易误判为页面卡死/加载失败而二次点击或离开,显著拉低感知性能与对"获取信息"的信心。
- **建议**:为 `/help` 路由增加骨架屏或 spinner/进度条作为加载 affordance;对该路由的 Remotion 视频与文章索引做代码分割/懒加载,优先渲染外壳布局,避免等待全部资源后一次性出现。

#### P1-3 未登录所有 CTA 殊途同归撞 `/login` 登录墙,与"本地优先/写作不需登录"宣传形成期望落差

- **现象与证据**:未登录主 CTA"开始写作 →"及"连接你的 AI""前往 JType Cloud""登录"**全部指向 `/login`**;徽标宣传"本地优先 MARKDOWN 库";落地后却是面向回头客的"**欢迎回来 / 登录您的 JType Cloud 账户**"登录墙;web 端无任何"试用/访客"路径。
- **用户影响**:"开始写作"暗示马上能写,实际撞上登录墙且以"欢迎回来"对待新访客;多个不同标签的入口塌缩成同一目的地,既是期望落差也是冗余路径,直接增加首访放弃成本、影响新用户转化。直接命中用户对"引导是否友好""文案是否词不达意"的关切。
- **建议**:区分 CTA 意图——"开始写作"走访客/试用或注册而非"欢迎回来"登录页;"连接你的 AI"走对应连接文档;仅"登录"进登录页。若 web 必须登录,则把主 CTA 文案改为与行为一致(如"免费注册开始"),并在登录页对新访客突出注册入口、避免假设回头客。

#### P1-4 中文界面泄漏英文复数"文件s",且面板计数(3)与实列文档数(4)不一致

- **现象与证据**:仪表板文档面板标题写"**3 个 Markdown 文件s**",但下方实际列出 **4 个文档**(`jcode.board`、`jcode/111`、`tech/oauth`、`test`,各带 Markdown chip)。英文复数 `s` 拼接到中文"文件"后变成"文件s"(i18n 复数规则未本地化);计数疑似按 3 个顶层树节点计、列表展平为 4。
- **用户影响**:同一字符串两处缺陷叠加——(a)全站中文界面突现英文复数尾巴,是肉眼可见的本地化缺陷,且出现在核心产品页最显眼的面板标题,破坏专业感与质量信任;(b)标题数字与实际可见列表不符,属展示错误,会误导用户对文档数量的认知。
- **建议**:修复计数口径使标题数字与实际渲染条目数一致(统一按展平文档数,或按节点数并相应改措辞);同时为 zh 使用单一复数形式(如 lingui plural 仅保留 `other`:`{count} 个 Markdown 文件`),移除拼接式英文 `s`;排查同类"N 个文档/文件"字符串是否都走正确复数规则。

#### P1-5 对外公开页 `/u/jack` 空状态为英文 `No published workspaces yet.` 且无任何导航出口

- **现象与证据**:公开主页为 `logo + jack + No published workspaces yet.`——该空状态文案是**英文**(全站其余为简体中文);空状态非常简陋,无导航/页脚/返回链接,也无"去创建你的站点"引导。
- **用户影响**:这是面向外部访客的**对外门面页**,出现全站唯一一处英文且是最显眼的核心提示,暴露翻译覆盖不全,损害发布者在访客面前的形象、破坏信任一致性;同时访客落到此页是死胡同,无任何前往帮助/主站/了解 JType 的路径。
- **建议**:将空状态文案本地化为中文(如"该作者还没有发布任何工作区"),并补一句引导(对站主显示"去发布你的第一篇",对访客显示"了解 JType"链接);公开页增加最小导航/页脚(品牌回 JType、帮助入口);排查 `/u/*` 整套字符串是否漏接 i18n 目录。

#### P1-6 `<html lang="en">` 与全站中文 UI 不符,语言属性错误

- **现象与证据**:`<html lang="en">`,但全站 UI 为中文;`viewport` meta 存在。
- **用户影响**:`lang` 属性错误会误导屏幕阅读器以英文发音引擎朗读中文、影响浏览器翻译提示与搜索引擎语言判定,是无障碍与 SEO 层面的全局性真实问题,影响所有用户,属破坏信任的不一致。
- **建议**:将根 `<html lang>` 设为与实际 UI 语言一致(当前 `zh-CN`),并在接入语言切换器后让 `lang` 随当前语言动态更新;确保 SSR/SPA 首帧即输出正确 `lang`。

### P2 — 中(11 项,另含 2 条并列说明)

#### P2-1 帮助中心文章页无常驻文章侧边栏,跨文章切换需 2 次点击

- **现象与证据**:文章页**没有常驻的文章侧边栏**;跨分类跳另一篇文章 = 点 tab → 点文章 = 2 次点击。(文章页本身有面包屑、最后更新时间、右侧 TOC、表格、代码块。)
- **用户影响**:连续查阅多篇文档(典型帮助消费模式)时每次切换都要回到索引页再下钻,来回跳转累积冗余点击,难以建立全局结构感。
- **建议**:在文章页加常驻左侧文章导航侧边栏(当前分类全部文章 + 可折叠其他分类),实现 1 次点击切换任意文章;桌面端尤其需要,现有右侧 TOC 保留用于页内跳转。

#### P2-2 帮助中心 7 个分类导航同屏重复两次(顶部 tab + 正文卡片),href 相同

- **现象与证据**:7 个分类同时出现两次——既是顶部子导航 tab(快速上手/仓库与编辑/同步与工作区/看板/发布/AI与MCP/命令行 + 案例),又是正文"按主题浏览"卡片,二者 `href` 完全相同(`/help/c/{cat}`)。
- **用户影响**:同一组入口在一屏内重复两遍且目标完全一致,是纯冗余,增加扫描成本、稀释信息密度,让用户怀疑两者点击效果是否不同。
- **建议**:二选一——保留正文"按主题浏览"卡片(带图标/描述、信息量更大),顶部 tab 改为滚动后吸顶的快速跳转条;或保留 tab 去掉冗余卡片。避免完全同 `href` 的重复入口。

#### P2-3 帮助中心顶栏与英雄区两个等价搜索框(placeholder 完全相同)

- **现象与证据**:顶栏一个 + 英雄区一个搜索框,placeholder 都是"搜索帮助中心…"。(搜索本身有效:输入即出 typeahead 结果,带分类 chip,1 次点击到文章。)
- **用户影响**:两个功能完全相同的搜索框同屏,制造视觉与决策冗余,用户需判断二者是否有差异,并占用首屏宝贵空间、稀释主操作。
- **建议**:首屏只保留英雄区大搜索框作为主入口;顶栏搜索框改为滚动后吸顶(sticky-on-scroll)出现,二者不同屏即可消除重复感;或直接合并为一个。

#### P2-4 "What is JType"讲解视频在 hub 与每个分类页重复出现

- **现象与证据**:"What is JType / 90 秒了解"讲解视频在 hub 和每个分类页都重复出现。
- **用户影响**:同一段入门视频在每层索引页重复挤占首屏,把用户与真正想找的文章正文不断往下推,增加滚动成本、降低单位屏幕信息密度。
- **建议**:入门视频只在 hub 出现一次;分类页移除该视频,把首屏让给该分类的文章列表/正文预览,缩短到达内容的距离。

#### P2-5 仪表板两个绿色主按钮互相竞争("发布草稿" vs "新建文档"),未选中即可触发批量发布

- **现象与证据**:发布面板主(绿色)按钮"发布草稿"与主区绿色"新建文档"形成两个互相竞争的主操作;即使没有选中任何文档,"发布草稿"(批量发布)视觉上仍是全屏最显眼的操作;数据显示"0 已发布 / 4 仅草稿"。
- **用户影响**:新用户进仪表板的首要任务是写作/新建,但视觉权重最高的却是危险性更高的批量"发布草稿",主操作指向被稀释甚至误导,存在无意触发全量发布的风险。
- **建议**:建立单一主操作层级——"新建文档"设为唯一实心主按钮,"发布草稿"降为次级样式(描边/中性色)并明确批量作用域;未选中文档时弱化或加二次确认,避免误触批量发布。

#### P2-6 全站无页脚,缺二级导航与快速回到帮助的兜底出口

- **现象与证据**:整页**没有任何页脚**,页面在末尾 CTA 卡片处直接结束,没有二级导航/链接/版权/快速回到帮助。结合移动端顶部导航又已塌缩不可见。
- **用户影响**:用户滚到长落地页底部后无任何导航出口,桌面需手动滚回顶部才能切换区块或进入帮助;移动端顶部导航已隐藏、底部更无路径,浏览动线在底部断掉。页脚缺失也使移动端导航缺口(P0)失去一层兜底。
- **建议**:增加标准页脚——分组链接(产品/帮助/AI/GitHub/法务)、版权、回到顶部,作为顶栏之外稳定的二级导航兜底;桌面与移动均受益。

#### P2-7 帮助页头与站点头不一致,返回主站区块仅靠点 logo 这一隐性手势

- **现象与证据**:帮助页头与站点头不同(帮助子导航替换了营销导航);只有点 logo 能回 `/`。
- **用户影响**:进入帮助后失去通往 流程/界面/AI/发布 等主站区块的直接入口,跨区块可达性断裂,用户需先猜到"点 logo"才能返回主站。
- **建议**:帮助页头保留指向主站的清晰链接(或在子导航旁并列主站入口),不要让返回主站仅依赖 logo 这一隐性手势。

#### P2-8 全站无暗色模式 / 无主题切换,缺 `color-scheme` meta,bodyBg 恒为白色

- **现象与证据**:全站(web)无暗色模式/无主题切换——无 `data-theme`、无 `color-scheme` meta、无任何主题切换控件、localStorage 无主题键;bodyBg 恒为白色。
- **用户影响**:偏好暗色或低光环境、对亮屏敏感的用户无法获得暗色体验;缺 `color-scheme` meta 还会导致系统暗色偏好下原生表单控件等配色不一致。存在亮屏刺眼摩擦但有(忍受亮色)变通。
- **建议**:至少补 `<meta name="color-scheme" content="light dark">` 并提供基于 `prefers-color-scheme` 的暗色变量;进一步加入显式主题切换控件并用 localStorage 持久化,与桌面端主题引擎对齐。

#### P2-9 落地页英雄区演示图中英文混排同框

- **现象与证据**:英雄区演示图内"已同步/云工作区/公开链接"(中)与 `version saved / device cursor advanced / publish check passed / Spring release notes / Local by default. Cloud when the team needs it.`(英)同框混排。
- **用户影响**:落地页首屏是第一印象,中英文夹杂的演示图让中文用户感到本地化不彻底、像半成品截图,削弱说服力;属展示物料问题,非功能阻断。
- **建议**:把演示图英文文案整体替换为中文,或为不同语言准备对应语言的 mockup 资源,保证首屏只出现一种语言。

#### P2-10 "语言"切换器不显示当前语言,无状态指示

- **现象与证据**:帮助页头有"语言"切换按钮,但不显示当前语言指示。
- **用户影响**:用户无法从控件确认当前处于哪种语言、切换后也得不到状态反馈,多语用户摩擦明显,但有变通(点开即可见选项)。
- **建议**:在切换器上直接显示当前语言(如"中文 ▾"),下拉中对当前语言加选中标记,切换后给出明确当前态。

#### P2-11 顶栏退出为纯图标(方框样字形),字形含义不明确

> 直接对应用户诉求一:"图标文案是否词不达意"。

- **现象与证据**:顶栏退出是纯图标(方框样字形),`aria-label="退出登录"`,仅靠悬停 tooltip;字形本身含义不明确。
- **用户影响**:退出是带后果的操作,靠一个语义不清的方框图标 + 仅悬停才出现的提示——桌面需悬停才知道,移动端无悬停更易误解或误触,达意性差。
- **建议**:换用语义明确的退出图标(如带箭头的 logout 图标),桌面端补可见文字标签"退出"或至少保证图标一眼可辨;保留 `aria-label`。

#### (并列)落地页英雄区与"产品流程"之间约一屏高空白留白

- **现象与证据**:桌面端英雄区演示图与"产品流程"区块之间有一大段空白(约一屏高的留白)。
- **用户影响**:桌面大屏下出现疑似断裂的空旷区域,用户可能误以为内容到此结束而停止下滑,错过下方产品介绍;属打磨缺失。
- **建议**:收紧该 section 间距(响应视口高度的合理 margin/padding),或在空白处填充过渡内容/滚动提示,引导继续浏览。
- **分级说明**:原始严重度 P3,因与落地页首屏说服力直接相关、与上方落地页打磨问题成组,故随落地页一并陈述;团队可按 P3 排期处理。

#### P3-1 仪表板"新建文档"重复出现两次(左栏 + 主区)

- **现象与证据**:"新建文档"出现两次(左栏 + 主区)。

#### P3-2 `?doc=` 深链参数不自动打开文档,需手动再点一次

- **现象与证据**:`?doc=` 深链参数不会自动打开文档(需手动点击)。*(原证据标注 confidence=low,待复核。)*
