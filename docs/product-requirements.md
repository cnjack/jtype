# JType Markdown Service PRD

## 1. 背景

当前 JType 是一个 Tauri 桌面 Markdown Viewer，核心能力是选择一个本地 Markdown 文件、渲染预览并显示源码。下一阶段希望它不再只是“单文件查看器”，而是升级为一个面向个人知识库、文档站点和轻量内容发布的 Markdown 工作台。

产品需要继续保留当前能力：用户可以从本地打开单个 Markdown 文件。同时新增文件关联打开、拖拽打开、目录管理、跨设备编辑、发布和后续 AI 能力的基础设计。

## 2. 产品愿景

JType 是一个 local-first 的 Markdown 内容工作台：用户可以把本地文件夹变成可管理、可编辑、可发布、可被 AI 理解的内容空间。

它应该兼顾三件事：

- 像本地编辑器一样可靠：用户的 `.md` 文件仍然在本地、可迁移、可用其他工具打开。
- 像内容管理服务一样有秩序：支持目录、站点结构、发布状态、资源管理和版本历史。
- 像 AI 原生工具一样可扩展：文档、目录、元数据、引用关系和操作历史都能被结构化消费。

## 3. 目标用户

- 个人知识管理用户：希望维护笔记、文档、资料库，并在多个设备继续编辑。
- 技术写作者和开发者：希望用 Markdown 管理文档站、README、教程和 changelog。
- 小团队内容维护者：希望低成本管理文档目录、发布页面、协作审阅。
- 后续 AI 功能用户：希望让 AI 帮忙总结、改写、生成目录、补充链接、检查文档一致性。

## 4. 目标

- 从单文件查看器升级为 Markdown 工作区。
- 支持本地文件夹作为 workspace，保留普通 Markdown 文件结构。
- 支持打开单个 Markdown 文件，包括系统文件关联和拖拽打开。
- 支持目录树管理：新建、重命名、移动、删除、排序、搜索。
- 支持编辑、预览、保存和资源引用管理。
- 支持发布为可访问页面或静态站点。
- 为后期 AI 能力建立清晰的数据模型、内容索引和扩展接口。

## 5. 非目标

- MVP 不做完整 Notion 类块编辑器。
- MVP 不强依赖云端账号，优先 local-first。
- MVP 不做复杂实时多人协作，后续可以通过同步和评论能力扩展。
- MVP 不把 Markdown 转成私有格式；文件本身必须仍然是普通 `.md`。

## 6. 使用场景

### 6.1 单文件继续打开

用户双击 `.md` 文件，或在系统“打开方式”中选择 JType，JType 打开该文件并显示编辑与预览界面。

用户也可以把 `.md` 文件拖入窗口，JType 直接打开它。如果拖入的是文件夹，JType 将它作为 workspace 打开。

### 6.2 管理一个 Markdown 目录

用户打开一个本地文件夹，例如 `docs/` 或 `notes/`。JType 读取其中的 Markdown 文件和资源文件，展示目录树。用户可以新建文章、移动文件、重命名路径、批量整理目录。

### 6.3 编辑和预览

用户在编辑区修改 Markdown，右侧或分屏区域实时预览。保存后写回本地文件。JType 识别 frontmatter、标题、链接、图片和附件。

### 6.4 发布文档

用户选择一个 workspace 或其中的一个目录作为站点，配置站点标题、导航、slug、发布目标。发布目标可以是 JType Cloud、静态站点导出、Git 仓库或对象存储。

### 6.5 AI 辅助准备

用户希望后续让 AI 理解当前文档集合。JType 需要维护结构化索引：文档标题、路径、frontmatter、Markdown AST、链接关系、资源引用、最近编辑记录和可选语义分块。

## 7. 核心功能需求

### 7.1 文件打开与入口

优先级：P0

- 支持通过按钮选择本地 `.md`、`.markdown`、`.mdown`、`.mkd` 文件。
- 支持系统文件关联，让用户可以双击 Markdown 文件或从“打开方式”启动 JType。
- 支持拖拽文件到窗口打开。
- 支持拖拽文件夹到窗口作为 workspace 打开。
- 支持最近打开文件和最近 workspace。
- 单文件模式下不强制生成 workspace 元数据。

验收标准：

- 双击关联的 Markdown 文件后，JType 能读取并显示该文件。
- 拖拽单个 Markdown 文件后，当前编辑区切换到该文件。
- 拖拽文件夹后，左侧目录树展示其中 Markdown 文件。

### 7.2 Workspace 和目录管理

优先级：P0

- 支持打开本地文件夹作为 workspace。
- 左侧展示目录树，区分文件夹、Markdown 文件、资源文件。
- 支持新建文件、新建文件夹、重命名、移动、删除。
- 支持根据标题、路径、标签和全文搜索。
- 支持空目录、隐藏文件、非法路径和重复文件名的异常处理。
- 支持 `.jtype/` 元数据目录，用于缓存索引、发布配置和 AI 预处理数据。

验收标准：

- 用户在 JType 中移动文件后，本地文件系统同步变化。
- 删除操作进入系统回收站或提供明确确认。
- 重命名文件后，内部链接可以提示是否同步更新。

### 7.3 Markdown 编辑和预览

优先级：P0

- 支持源码编辑。
- 支持实时预览。
- 支持 GitHub Flavored Markdown。
- 支持 frontmatter 识别和可视化编辑入口。
- 支持图片和附件引用预览。
- 支持未保存状态、保存、另存为。
- 支持基本编辑快捷键。

验收标准：

- Markdown 内容保存后，本地文件内容正确更新。
- 预览渲染经过 HTML sanitization，避免注入风险。
- 文件变更来自外部编辑器时，JType 能提示刷新或合并。

### 7.4 内容元数据

优先级：P1

- 支持 YAML frontmatter。
- 常用字段包括 `title`、`description`、`tags`、`slug`、`status`、`createdAt`、`updatedAt`、`publish`。
- 支持按标签、状态、更新时间筛选。
- 支持文档间双向链接索引。
- 支持缺失标题、重复 slug、断链图片的检查。

验收标准：

- 修改 frontmatter 后能写回 Markdown 文件。
- 搜索和筛选结果能基于 frontmatter 更新。
- 发布前检查能列出阻塞项和建议项。

### 7.5 发布

优先级：P1

- 支持将 workspace 或指定目录发布为站点。
- 支持发布单篇文档。
- 支持草稿、已发布、已下线状态。
- 支持站点导航、首页、目录顺序、slug 配置。
- 支持本地预览发布结果。
- 支持导出静态站点。
- 后续支持 JType Cloud、GitHub Pages、S3/R2 等目标。

验收标准：

- 用户可以选择一篇文档并生成发布预览。
- 发布输出中的链接、图片和代码块可正常访问。
- 未设置 `publish: true` 或状态为 draft 的文档不会默认公开发布。

### 7.6 跨设备和服务能力

优先级：P2

- 支持账号登录。
- 支持 workspace 同步。
- 支持冲突检测和冲突解决。
- 支持发布历史和回滚。
- 支持团队空间、权限和审阅。

验收标准：

- 同一账号在两台设备打开同一 workspace 时，可以看到同步状态。
- 离线编辑后联网能继续同步。
- 同一文件的并发编辑出现冲突时，不静默覆盖。

### 7.7 AI 友好能力

优先级：P1 设计先行，P2 功能落地

- 为每个 workspace 维护机器可读索引。
- 为每篇文档生成稳定 document id，不依赖可变路径。
- 解析 Markdown AST，提取标题层级、段落、代码块、表格、链接和图片。
- 保存文档引用关系、标签、发布状态和最近编辑事件。
- 支持按标题和语义块构建 chunk，后续可接入 embedding。
- 为 AI 操作预留 command layer，例如总结、改写、生成目录、修复链接、补充 frontmatter。
- 所有 AI 写入都应支持 diff 预览和用户确认。

验收标准：

- 本地索引能够回答“有哪些文档、每篇文档标题是什么、引用了哪些资源”。
- AI 建议类操作不会直接覆盖文件，必须能展示变更差异。
- 索引数据可以从文件系统重新构建，不能成为唯一真实来源。

## 8. 信息架构

主要对象：

- Workspace：一个本地目录或云端同步空间。
- Document：一个 Markdown 文件。
- Folder：目录树节点。
- Asset：图片、附件、视频等资源文件。
- Site：一个可发布站点配置。
- PublishTarget：发布目标。
- Revision：文件版本或发布版本。
- AIContext：为 AI 消费准备的结构化上下文。

推荐 workspace 结构：

```text
my-docs/
  .jtype/
    workspace.json
    index.sqlite
    publish.json
    ai-context.jsonl
  articles/
    hello.md
  assets/
    cover.png
```

`.md` 文件仍然是主数据，`.jtype/` 只保存缓存、配置和可重建索引。

## 9. 核心体验

### 9.1 主界面

- 左侧：workspace 目录树、搜索、最近文件。
- 中间：Markdown 编辑器。
- 右侧：预览、属性、发布、AI 面板按 tab 切换。
- 顶部：当前 workspace、保存状态、发布状态、全局命令。

### 9.2 单文件模式

- 没有目录树时，界面专注于当前文件。
- 用户可以选择“把所在文件夹作为 workspace 打开”。
- 拖入新文件时直接替换当前打开文件。

### 9.3 Workspace 模式

- 默认显示目录树。
- 打开文件时保留多标签或最近访问列表。
- 允许批量重命名和移动。
- 发布状态在目录树中可见。

## 10. 权限和安全

- 本地文件访问需要通过用户显式选择文件或目录授权。
- Markdown 渲染必须经过 HTML sanitization。
- 发布前必须区分本地私有文件和公开输出。
- AI 功能不得默认上传 workspace 内容，必须明确授权。
- 日志中避免记录完整私密文档内容。

## 11. 成功指标

- 用户能在 30 秒内打开一个本地 Markdown 文件并开始编辑。
- 用户能在 2 分钟内打开一个目录并找到目标文档。
- 用户能在 5 分钟内完成一次本地发布预览。
- 打开 1,000 个 Markdown 文件的 workspace 时，目录树和搜索仍保持可用。
- 由 JType 写入的 Markdown 文件可以被其他编辑器正常打开。

## 12. 分阶段路线图

### Phase 0：当前基础能力

- 单文件打开。
- Markdown 渲染预览。
- 源码展示。

### Phase 1：本地编辑器可用版

- 文件关联打开。
- 拖拽打开文件。
- 源码编辑和保存。
- 最近文件。
- 基础错误处理。

### Phase 2：Workspace 版

- 打开文件夹。
- 目录树管理。
- 文件搜索。
- 图片和附件管理。
- `.jtype/` 本地索引。

### Phase 3：发布版

- 发布配置。
- 本地站点预览。
- 静态站点导出。
- 单篇发布和目录发布。

### Phase 4：服务版

- 账号和同步。
- 发布托管。
- 发布历史。
- 团队权限。

### Phase 5：AI 原生版

- 内容索引和语义分块。
- AI 命令面板。
- 文档问答。
- 批量改写、总结、修复链接。
- AI 变更 diff 和审阅。

## 13. 待确认问题

- 产品命名是否从 Markdown Viewer 改为 JType。
- 发布目标第一优先级是静态导出、GitHub Pages，还是自建 JType Cloud。
- 编辑器内核选择：轻量 textarea、CodeMirror 6，还是 Monaco。
- 是否需要 Git 集成作为版本管理基础。
- 云同步是否自研，还是先接入用户已有 Git/云盘目录。
