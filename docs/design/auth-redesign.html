登录与授权体验 · 改进设计稿

解决三处入口的问题：桌面端授权流程"戛然而止"、Web 验证码输入框不够好看、三处视觉不统一。 所有设计严格沿用现有 design tokens（brand #008884、rounded-2xl 卡片、focus-ring 反馈、JetBrains Mono 品牌字）。 设计稿中"验证码"指的是 OAuth device-flow 的 6 位 user_code，不是短信/邮箱验证码。

04

共享组件抽取草图

按现有 shared/ 架构（Props-in / Callbacks-out），把上面三处复用的部分抽成共享组件， 桌面端和 Web 端共用同一套实现，避免再次分裂。下面是 props 设计草图（未实现）。

{ shared/components/OTPInput.tsx 
// 6 位验证码输入（device-flow user_code 专用）
// Web DeviceOAuth 页 + 未来桌面端 fallback 共用

interface OTPInputProps {
  length: number;              // 默认 6
  value: string;              // 受控值
  onChange: (v: string) => void;
  onComplete?: (v: string) => void;  // 填满自动提交
  error?: boolean;           // 红色高亮
  groupSize?: number;       // 分组，默认 3-3
  autoFocus?: boolean;
}

// 内置能力：自动跳格 / Backspace 回退 /
// 整串粘贴拆分 / inputmode=numeric

纯 props 驱动，无任何平台耦合。Web 和桌面端各自传入 onChange/onComplete 调各自的 API。

{ shared/components/AuthCard.tsx 
// 统一的认证卡片外壳（brand 背景 + 白色表单卡片）
// Login 页 + DeviceOAuth 页共用

interface AuthCardProps {
  brand?: ReactNode;          // 左侧品牌面板，可省略
  title: ReactNode;
  subtitle?: ReactNode;
  icon?: ReactNode;           // 顶部图标
  children: ReactNode;       // 表单内容
  footer?: ReactNode;         // 底部切换链接
  split?: boolean;           // 是否分屏，默认 true
}

// 视觉一致性保证：
// - 固定 #f5f8f6 背景
// - rounded-2xl + ring-1 ring-black/[0.03]
// - JetBrains Mono 品牌字标

把"卡片质感"固化在一个组件里，从此三处认证页天然视觉统一， 后续新增认证页（如邀请接受、密码重置）也自动复用。

设计原则：克制、延续现有"local-first 安静工具"的气质，不堆装饰。核心是补全反馈闭环 （倒计时、进度、状态可见性、明确的动作）和视觉统一，而非换皮。

取舍说明：本轮聚焦明色模式，未做暗色变体（后续可补）； 未引入第三方社交登录（后端无此能力）；"验证码"仅指 device-flow user_code， 未臆造短信/邮箱 OTP 功能。所有倒计时（10 分钟）对齐后端 services/jtype-web/src/util.rs 的 short_user_code 生命周期。
