JType 的发布功能刻意保持简单：你逐篇决定哪些笔记公开，方式就是编辑笔记本身。这里没有单独的"导出"流程，也不存在另一份需要保持同步的内容副本——仓库里的 Markdown 文件始终是唯一的事实来源。

## 标记一篇笔记为发布

只要某篇笔记的 YAML frontmatter 里包含 `publish: true`，它就会变为公开。frontmatter 是文件最顶部用 `---` 围起来的小块。如果你的笔记还没有，请在正文第一行上方补上。

```markdown
---
title: JType 入门
publish: true
---

# 入门

这一页现在已经成为你公开站点的一部分。frontmatter
下方的所有内容都会作为普通 Markdown 页面渲染。
```

**没有** `publish: true`（或写成 `publish: false`）的笔记会完全保持私有——它们存在于你的仓库中、会同步到工作区，但永远不会出现在公开网络上。发布是逐文件的主动选择，因此不会有内容意外泄露。

你可以在桌面编辑器、网页端，或直接通过 [CLI](/help/c/cli/notes-bind-sync) 添加这一行——它不过是文件里的一段文本而已。

## 公开站点长什么样

你发布的笔记会汇集成一个只读的**站点**。首页位于：

```text
/u/你的用户名
```

每篇已发布的笔记都有自己的页面，以它在仓库中的路径作为标识：

```text
/u/你的用户名/:page_path
```

于是一个像 `guides/getting-started.md` 的仓库文件，就会变成站点上一个干净、可分享的页面。读者看到的是渲染后、可导航的 Markdown 版本——标题、链接、代码块、表格、公式和图表都会保留。他们看不到你的编辑器、你的账号，也看不到未发布的草稿。

## 源文件始终是 Markdown

发布绝不会把你的笔记转换成别的格式。仓库里的 `.md` 文件依旧是纯 Markdown——你可以用任何编辑器打开、在文件夹间移动，或用任意方式备份。取消发布同样简单：删掉 `publish: true` 这一行（或改成 `false`），下一次同步时该页面就会从站点上消失。

正因为文件就是事实来源，你的已发布页面和正在编辑的笔记不会出现你看不见的偏差——文件里是什么，站点上就是什么。

## 让它上线

发布依托于云端工作区，正是它在对外提供公开站点。如果你还没有连接工作区，请先阅读[云端工作区与绑定](/help/c/sync-workspaces/cloud-workspaces)，然后[把改动推送上去](/help/c/sync-workspaces/push-pull-sync)，让已发布的笔记到达服务器。
