JType 只围绕一个理念构建：**你的笔记就是存放在本机上的纯 Markdown 文件。** 其余的一切——云端同步、看板、发布、AI——都是你按需选择启用的：逐个文件、逐个工作区，只在真正有需要时才用。

需要理解四个概念。想通了它们，JType 的其余部分就一目了然。

## 仓库（Vault）

**仓库**就是你设备上一个普通的 Markdown（`.md`）文件夹。没有专有数据库，也没有“导出”这一步——这个文件夹*本身*就是唯一可信来源。

- 你可以保留惯用的子文件夹（`meetings/`、`projects/`、`daily/`）。
- 你可以用任何其他编辑器打开同一个文件夹；JType 绝不锁定你的文件。
- 默认仓库位于 `~/Documents/.jtype`，但你可以打开任意文件夹。

> 哪怕你明天不再使用 JType，留下的仍是一个干净的 Markdown 文件夹。这正是*本地优先*的意义所在。

## 云端工作区（Cloud workspace）

**云端工作区**是一切协作功能的可选在线边界：同步、共享、看板、发布、存储额度与成员管理。

写作并不需要它。当你*确实*想把某条笔记带到另一台设备、让同事参与，或在网页上发布一个页面时，再把仓库绑定到工作区即可。

## 绑定（Binding）

**绑定**是单台设备上“一个云端工作区 ↔ 一个本地仓库路径”的映射。它就保存在你文件旁边的 `.jtype/cloud.json` 中，于是每台机器都知道哪个文件夹对应哪个工作区。

绑定之后，**同步**就是一次双向的推送/拉取：你本地的修改上传，别人的修改下载，当同一条笔记在两处都改动时，JType 会帮你解决冲突。

## 站点（Site）

**站点**是选定笔记发布后的只读输出。在某条笔记的 frontmatter 中加上 `publish: true`，它就会成为你在 `/u/:username` 上公开站点的一部分，而源文件仍是仓库里的 Markdown。

## 串联起来

```text
  本地仓库     ──绑定──▶   云端工作区        ──发布──▶    公开站点
  (你的文件)              (同步 · 看板 · 成员)          (/u/你)
       ▲                          ▲
       └────── jtype 命令行 ───────┘
       └────── 通过 MCP 接入 AI ───┘
```

典型的一周是这样的：

1. 在桌面应用的仓库里**写作**——本地、快速、私密。
2. 当你想把内容带到另一台设备或与同事共享时，**同步**到云端工作区。
3. 在同一个工作区里用看板**梳理**工作。
4. **发布**那些应当公开的笔记。
5. 让 AI 助手通过 MCP 读取并更新笔记与卡片，把繁琐的部分**自动化**。

你完全可以永远停在第 1 步，JType 依然是一款出色的本地 Markdown 编辑器。后面的每一步都在你需要时才出现——绝不提前打扰。
