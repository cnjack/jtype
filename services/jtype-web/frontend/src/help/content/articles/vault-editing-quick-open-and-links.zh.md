一个装着上百条笔记的仓库，只有在你能一秒钟找到正确那条时才真正好用。JType 提供了几种简单的穿梭方式——并让你把笔记连接起来，使相关的想法始终只隔一次点击。

## 文件导航

在仓库模式下，侧边栏映射着你磁盘上的文件夹。它就是你全部内容的地图：

- 点击文件夹将其展开；点击笔记便在编辑器中打开它。
- 这棵树反映仓库里真实的子文件夹——和你在访达或资源管理器里看到的一模一样。
- 你在这里新建的笔记和文件夹，会立刻成为磁盘上真实的文件。

这是从容、审慎的浏览方式。要追求速度，就用快速打开。

## 快速打开

**快速打开**是跳转到某条笔记最快的方式：开始输入它名称的一部分，再从列表里选中它，全程双手不离键盘。

- 输入标题或路径的几个字母——结果会随之逐步缩小。
- 按回车打开排在最前的结果。
- 它会跨所有文件夹搜索，所以你无需记得某条笔记存放在哪里。

当你大致知道一条笔记叫什么时，快速打开每一次都胜过在树里一层层点击。

## 文档信息

为正在编辑的笔记打开**文档信息**，即可一眼看清它的细节——它在仓库中的路径，以及它携带的 frontmatter 值，例如 `title` 和是否设置了 `publish`。在同步或发布之前，这是确认一条笔记是否按你预期配置好的最快方式。关于 frontmatter 的更多内容，参见[撰写 Markdown](/help/c/vault-editing/writing-markdown)。

## 把笔记连接起来

仓库真正的威力，在笔记彼此指向对方时显现。JType 支持 **wikilink**——把一条笔记的名称用双方括号括起来：

```markdown
时间线请看 [[发布计划]]。

你也可以为链接重新命名显示文字：[[launch-plan|完整计划]]。
```

- `[[发布计划]]` 链接到名为*发布计划*的笔记，并显示这段文字。
- `[[launch-plan|完整计划]]` 链接到 `launch-plan`，但显示为“完整计划”。

在预览中，wikilink 是可点击的：选中它，JType 就会在你的仓库里打开目标笔记。由于链接以纯文本形式存放在文件里，即使你用其他编辑器打开这条笔记，它依然保有意义。

对于仓库之外的任何内容，标准 Markdown 链接同样有效：

```markdown
[JType 的 GitHub 仓库](https://github.com/cnjack/jtype)
```

## 一套实用的循环

1. 用**快速打开**进入你想动手的那条笔记。
2. 写作，并在提到相关笔记时用 `[[...]]` **链接**过去。
3. 查看**文档信息**，确认标题和发布标记无误。
4. 当你想浏览整个文件夹、而不是跳到单条笔记时，使用**文件导航**。
