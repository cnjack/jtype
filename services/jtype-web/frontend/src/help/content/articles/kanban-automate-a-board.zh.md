看板事件让其他服务能在卡片创建或变更时作出响应。你可以触发部署系统、驱动智能体、刷新仪表盘，或运行其他工作流，而不必反复扫描全部卡片。

在网页应用中打开看板，点击看板工具栏里的齿轮进入**看板设置（Board settings）**，然后选择 **Webhooks**。这里显示的每个地址，都已经限定到你当前打开的看板。

## 选择事件传递方式

- **推送（Push / HTTP）**会在卡片变化后立即向你的 HTTPS 端点发送带签名的请求。适合拥有稳定公网端点、并希望低延迟响应的服务。
- **按 sequence 拉取（Pull）**让服务按自己的节奏查询变更。适合定时任务、智能体、内网服务，以及停机后必须可靠恢复的工作流。
- **实时 SSE** 会保持一条类似浏览器的长连接并立即显示新事件。它适合在线仪表盘和联调，但不是持久恢复游标。如果不能遗漏任何事件，断线后请用 sequence 拉取补齐。

推送和拉取只是同一批卡片事件的不同传递方式。使用 Pull 之前，不需要先创建 Push webhook。

## 用 sequence 游标可靠拉取

在 **Pull** 页签里，JType 会显示 sequence 拉取地址和 **Pull once** 按钮。正式自动化应遵循同样的循环：

1. 第一次使用 `afterSequence=0`，之后读取自动化上次保存的游标。
2. 请求头带上 `Authorization: Bearer <session or MCP token>`。
3. 按顺序处理返回的 `events`。
4. 只有整批事件都处理成功后，才把 `nextSequence` 保存为下一次游标。
5. 如果 `hasMore` 为 true，立即用新游标拉取下一页。
6. 如果处理失败，保留旧游标，并从旧游标重试。

重试时可能再次拿到已经见过的事件。接收端应保持幂等，例如先记录事件的 `sequence`，避免同一次部署被启动两遍。

> sequence 编号属于整个工作区，而拉取地址会筛选到单个看板。编号有间隔是正常现象：缺少的编号可能属于另一个看板，并不代表事件丢失。

看板设置里的按钮也可以快速排障。创建或编辑一张卡片，点击 **Pull once**，确认事件出现在日志里且显示的游标向前推进。如果积压超过一页，按钮会变成 **Pull next page**。

## 理解卡片事件

- `kanban:card-created` 在卡片第一次保存时记录。
- `kanban:card-updated` 在后续编辑时记录，其中也包括把卡片移动到另一列。

每条事件都包含看板、卡片路径、标题、状态、编辑者和 sequence。卡片设置了优先级、负责人或截止日期时，这些可选字段也会一并返回。

## 使用 Push（HTTP）

在 **Push (HTTP)** 中填写名称和 HTTPS 目标地址，选择事件类型，然后点击 **Create**。请立即复制签名密钥——它只显示一次。接收端在执行动作前，应先校验 HMAC-SHA256 签名。

Webhook 列表会显示最近一次投递状态。投递失败会明确显示；端点没有收到通知时，JType 不会把自动化伪装成成功。

## 使用实时 SSE

点击 **Connect & test**，可以在设置窗口打开期间观察事件。由于浏览器的 `EventSource` API 无法附加授权请求头，SSE 会把 session token 放在 URL 中。含有该 token 的 URL 应当像密码一样保护，不要粘贴到日志或工单中。

服务器可能关闭空闲连接。重新连接即可继续接收新事件；如果要补回断线期间可能发生的事件，请使用 sequence 拉取。

## 保护凭据

Session 与 MCP token 会继承你账号的访问能力。MCP 地址里的看板只是默认起点，并不是权限边界：该 token 可以访问账号本身能访问的所有看板。请把 token 与 webhook 签名密钥存入密钥管理器，及时轮换已暴露的凭据，并只给集成所需的工作区权限。
