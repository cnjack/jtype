默认情况下，你发布的站点位于 `/u/你的用户名` 之下。自定义域名让同一个站点能从你自己拥有的地址访问——例如 `notes.example.com` 或 `example.com`——这样读者（以及搜索引擎）看到的是你的品牌，而不是一条共享路径。

自定义域名只改变*地址*，并不改变*发布的内容*：无论用哪个地址，出现的都是完全相同的那批笔记。

## 连接域名

自定义域名是在网页控制台中、针对你的云端工作区进行配置的。整个流程与你在其他服务上熟悉的一致：

1. 在工作区的站点设置中，添加你想使用的域名，例如 `notes.example.com`。
2. 在你的 DNS 服务商处，按控制台给出的记录把该主机名指向 JType（子域名用 `CNAME`，顶级域名则按列出的记录配置）。
3. 添加控制台提供的验证记录，让 JType 确认该域名归你所有。
4. 等待 DNS 生效并签发证书。完成后，你的域名就会直接提供该站点。

上线后，你的首页会在域名根路径响应，而每个已发布页面都保留其可读的路径：

```text
https://notes.example.com/                  →  /u/你的用户名
https://notes.example.com/guides/intro      →  /u/你的用户名/guides/intro
```

底层的 `/u/你的用户名` 地址也依然有效——自定义域名是额外的一扇大门，而不是替代品。

## 哪些会发布、哪些保持私有

自定义域名不会扩大可见范围。规则和默认地址下完全一致：

- **公开：** 只有 frontmatter 中包含 `publish: true` 的笔记。每篇都会成为你域名下的一个页面，由其 Markdown 以只读方式渲染。
- **私有：** 其余一切。没有 `publish: true`（或写成 `publish: false`）的笔记永远不会出现在站点上——根路径上没有、任何能猜到的路径上也没有、即便拿到正确的 URL 也访问不到。

无论使用什么域名，以下内容同样保持私有：

- 你的原始仓库文件夹，以及任何未标记发布的文件。
- 草稿、已归档的笔记，以及个人子文件夹。
- 你的看板、成员、账号和工作区设置。
- *其他*工作区的内容——一个域名绑定到某一个工作区的站点，因此它只能提供该工作区已发布的笔记。

换句话说：给站点套上一个域名只改变外壳，绝不改变内容。如果一篇笔记不是 `publish: true`，任何自定义域名都无法把它暴露出去。

## 公布之前再检查一遍

在分享链接之前，先在该域名下打开几个已发布页面，确认能访问到的只有你打算公开的内容。要下线某个页面，从笔记中删除 `publish: true`（或改成 `false`）并同步——它会像在默认地址上一样，从你的自定义域名上消失。
