**仓库（Vault）**是你在 JType 中写作的归处——而它出奇地朴素。它就是你自己设备上一个装满纯 Markdown（`.md`）文件的文件夹。这里没有专有数据库，也没有隐藏格式：这个文件夹*本身*就是你的笔记。

## 仓库就是一个普通文件夹

在访达、资源管理器或任意其他编辑器里打开你的仓库，你看到的正是意料之中的样子——一个个用肉眼就能读的 `.md` 文件。

- 默认仓库位于 `~/Documents/.jtype`，但你可以把任意文件夹作为仓库打开。
- 每条笔记都是单独的 `.md` 文件。像对待其他任何文件一样去重命名、移动或复制它。
- 因为只是纯文本，仓库能与你早已在用的备份、Git、Dropbox 和搜索工具无缝配合。

> 这个文件夹就是唯一可信来源。哪怕你明天离开 JType，留下的仍是一个干净、可随身带走的 Markdown 文件夹。

## 子文件夹由你随意安排

JType 会原样读取你放在磁盘上的结构。你想怎么分组就怎么分组：

```text
my-vault/
  daily/
    2026-06-14.md
  projects/
    launch-plan.md
  meetings/
    standup.md
```

无论是在应用里还是在文件管理器里新建文件夹，二者呈现的效果完全一致。这里没有强制的层级，也没有需要维护的标签数据库；你建的文件夹，就是你得到的导航。

## JType 绝不锁定你的文件

JType 会打开、读取并保存你的 `.md` 文件，但绝不对它们加独占锁。你可以在另一个应用里编辑同一条笔记，JType 会自动感知到改动。正因如此，把仓库放进 iCloud、Dropbox 或一个 Git 仓库里与其他内容并存，都是安全的。

## .jtype 文件夹存放本地状态

在你的笔记旁边，JType 会保留一个小小的 `.jtype/` 文件夹来记录自身的账本信息。其中最关键的是**云端绑定**：

```text
.jtype/
  cloud.json   # 本仓库绑定到了哪个云端工作区
```

当你把仓库连接到某个云端工作区以进行同步时，`cloud.json` 就会被写入。它是按设备区分的，因此同一个文件夹在另一台机器上可以独立地绑定到同一个工作区。你的笔记本身绝不会进入 `.jtype/`——它们始终是文件夹里普通的 `.md` 文件。想在终端查看当前的仓库根目录与绑定情况，运行 `jtype vault status`。

## 单文件模式与仓库模式

JType 提供两种打开 Markdown 的方式：

- **单文件模式**是面向单个 `.md` 文件的专注编辑器。这里没有导航、同步、账户或发布——只有你和这份文档。对于快速修改一个不属于任何仓库的文件来说，它再合适不过。
- **仓库模式**会打开整个文件夹，并解锁 JType 的其余能力：文件导航、快速打开、分屏预览、文档信息、发布检查，以及账户/云端同步。

你随时可以先从单文件模式开始，之后再打开一个仓库。无论怎么切换，你的文件本身都不会有任何改变。
