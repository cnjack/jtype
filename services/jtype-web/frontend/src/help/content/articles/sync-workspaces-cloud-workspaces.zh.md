在你做出决定之前，仓库完全属于你自己。**云端工作区**是一个可选的在线归处，让仓库在多设备间同步、与同事共享、承载看板，并支撑已发布的站点。你的 Markdown 文件始终原地不动——工作区只是你按需选择的边界，而不是笔记搬去的新地方。

## 什么是云端工作区

云端工作区是一切协作功能的服务端边界：

- **同步**——把本地的修改推送上去，把别人的修改拉取下来。
- **共享与成员**——邀请他人并分配角色（参见[成员与角色](/help/c/sync-workspaces/members-and-roles)）。
- **看板**——看板和卡片存放在工作区里，而非你的文件中。
- **发布**——你公开[站点](/help/c/publishing/publish-a-site)的内容来源。
- **存储额度**——按工作区计算的笔记存储额度。

你永远*不必*使用它。仓库完全可以离线工作。只有当你想把某条笔记带到第二台设备、让同事参与，或在网页上发布一个页面时，才需要绑定到工作区。

## 在网页端创建工作区

1. 打开你的 JType 网页服务（本地为 `http://localhost:13345`）并登录。
2. 新建一个工作区并命名。JType 会为它分配一个 id 和一个 slug。
3. 完成——工作区已就绪，可以接收仓库了。

## 在桌面端用浏览器 OAuth 登录

桌面应用从不索要密码。当你连接账户时，JType 会打开浏览器，你在网页服务中登录，授权再回流到应用。这与命令行和 AI 连接器使用的浏览器 OAuth 是同一套流程，因此你的凭据始终只存放在一个受信任的地方。

## 把仓库绑定到工作区

**绑定**是单台设备上的一条映射：**一个云端工作区 ↔ 一个本地仓库路径**。它写入 `.jtype/cloud.json`，就在你文件旁边，于是每台机器都知道哪个文件夹对应哪个工作区。该文件不保存任何密钥令牌——把它留在仓库里是安全的。

在命令行中，为当前目录所在的仓库执行绑定。你可以用 id、名称或 slug 指定工作区：

```bash
jtype login
jtype workspace list          # 找到工作区的 id / 名称 / slug
jtype bind --workspace "Team Docs"
jtype vault status            # 确认仓库根目录与绑定
```

`jtype vault status` 会显示 JType 检测到的仓库根目录（它会从当前文件夹向上查找 `.jtype/` 目录），以及它所绑定的工作区。

## 绑定之后

仓库一旦绑定，你的笔记命令仍是**本地优先**的——依旧读写工作目录里的 Markdown 文件。绑定只是告诉 `jtype sync` 该与哪个工作区通信。要了解双向流程以及冲突的处理方式，请参见[推送与拉取同步](/help/c/sync-workspaces/push-pull-sync)。

> 每台设备上，一个仓库路径对应一个工作区。你可以自由地把不同文件夹绑定到不同工作区——每个 `.jtype/cloud.json` 都相互独立。
